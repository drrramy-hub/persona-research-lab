# Contributing

Open an issue describing the research workflow, problem and proposed improvement. Use synthetic examples and never publish participant data, identifying details or credentials.

Run `python -m unittest discover -s tests -v` before proposing code changes. Keep tests for source validation, role boundaries and the human-review step. Avoid changes that silently treat model output as participant evidence.

Useful contributions include researcher-led usability evaluation, Arabic output review, accessibility improvements, qualitative-method guidance, Entra ID authentication and stronger semantic-support evaluation. Report the model, date, procedure and limitations for any live evaluation. Do not claim accuracy or adoption without evidence.

Treat contributors respectfully. Report sensitive vulnerabilities privately to the repository maintainer; never post credentials in public issues.
