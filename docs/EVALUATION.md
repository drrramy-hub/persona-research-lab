# Researcher-led evaluation guide

This is a proposed evaluation protocol, not a report of completed testing.

1. Obtain permission to use an anonymised study excerpt set. Retain a separate source-of-truth record outside the app.
2. Have a researcher independently identify candidate themes, exceptions and source context. Do not treat one human analysis as uniquely correct.
3. Record deployment name, date, prompt version and input records. Run live analysis and preserve the unedited export.
4. Inspect every quoted excerpt and cited source. For each interpretation, record supported / partly supported / unsupported, with rationale. Source matching alone is insufficient.
5. Assess omitted contradictions, erased minority perspectives, unsupported demographic assumptions and whether proposed persona boundaries are useful for the research question.
6. Edit and approve profiles only after review. Ask grounded questions and intentionally unanswerable questions. Check that unknowns are acknowledged rather than filled with invented biographies or preferences.
7. Compare responses with the approved profile and its permitted source set. Keep simulation output separate from the original corpus.
8. Test interface usability and accessibility with researchers. Review keyboard navigation, clear labels, screen-reader output and export interpretation.
9. Publish limitations alongside any results. Do not count synthetic answers as participants, calculate saturation from them or substitute them for fieldwork.

Possible descriptive measures: exact-quote match rate; source-ID validity; human-rated semantic support; unsupported-claim count; appropriate abstention on unanswerable questions; researcher correction effort. Define denominators, coding criteria and disagreement handling before reporting numbers. No target thresholds or performance results are asserted by this project.
